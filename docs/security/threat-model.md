## 개요

HnVue Console은 의료 영상 장비용 GUI 콘솔 소프트웨어로, IEC 62304 Class B/C 등급의 의료 기기 소프트웨어 요구사항을 준수해야 합니다. 이 문서는 시스템에 대한 체계적인 위협 모델링을 제공하여 보안 설계 및 구현의 기준이 됩니다.

### 시스템 아키텍처 개요

```
┌─────────────────────────────────────────────────────────────┐
│                    User Interface                          │
│                 (WPF MVVM Application)                     │
└─────────────────────┬─────────────────────────────────────┘
                      │
┌─────────────────────▼─────────────────────────────────────┐
│                   Console Application                      │
│           (HnVue.Console.exe)                            │
└─────────────────────┬─────────────────────────────────────┘
                      │
┌─────────────────────▼─────────────────────────────────────┐
│                   gRPC IPC Layer                          │
│                (TLS 1.3 + Mutual Auth)                    │
└─────────────────────┬─────────────────────────────────────┘
                      │
┌─────────────────────▼─────────────────────────────────────┐
│                 Hardware Layer                             │
│            (Medical Imaging Device)                       │
└─────────────────────────────────────────────────────────────┘
```

## 1. STRIDE 분석

### 1.1 Spoofing (사칭)

| 위협 요소 | 위험 등급 | 영향도 | 설명 |
|----------|----------|--------|------|
| 사용자 인증 우회 | **높음** | 기밀성 • 무결성 • 가용성 | 악성 사용자가 인증 시스템을 우회하여 승인되지 않은 기능에 접근할 수 있습니다. |
| 토큰 재생 공격 | **높음** | 기밀성 • 무결성 • 가용성 | 탈취된 인증 토큰을 재사용하여 비인가된 작업을 수행할 수 있습니다. |
| 세션 하이재킹 | **중간** | 기밀성 • 무결성 | 활성 세션을 탈취하여 사용자의 권한을 이용할 수 있습니다. |
| gRPC 메시지 위조 | **높음** | 기밀성 • 무결성 • 가용성 | gRPC 메시지 위조를 통해 장비 제어 명령을 조작할 수 있습니다. |

#### 완화 전략

1. **다단계 인증(MFA)**
   - 모든 관리자 계정에 MFA 적용
   - 하드웨어 보안 모듈(HSM) 통합
   - 1회용 패스워드(OTP) 지원

2. **강력한 세션 관리**
   - 세션 타임아웃: 15분 (관리자), 30분 (일반 사용자)
   - 동시 세션 제한: 최대 3개
   - 세션 ID 무작위 생성 및 변경

3. **gRPC 보안 강화**
   - TLS 1.3 필수 사용
   - 상호 인증(Mutual TLS)
   - 서버 인증서 핑거프린트 검증

### 1.2 Tampering (조작)

| 위협 요소 | 위험 등급 | 영향도 | 설명 |
|----------|----------|--------|------|
| 데이터 저장소 조작 | **매우 높음** | 무결성 • 가용성 • 안전성 | 디지털 영상 데이터, 환자 정보, 시스템 설정을 위조할 수 있습니다. |
| gRPC 명령 조작 | **매우 높음** | 무결성 • 안전성 | X선 노출, 이미징 설정 등 의료 장비 제어 명령을 조작할 수 있습니다. |
| UI 변경 | **중간** | 무결성 • 신뢰성 | 사용자 인터페이스를 변조하여 오해를 유발할 수 있습니다. |
| 설정 파일 변경 | **높음** | 무결성 • 가용성 | 시스템 설정을 변경하여 비정상적인 동작을 유발할 수 있습니다. |

#### 완화 전략

1. **데이터 무결성 보장**
   - 모든 데이터에 디지털 서명
   - 암호학적 해시(SHA-256) 검증
   - 쓰기 전 암호화(WORM) 저장소 사용

2. **입력값 검증**
   - 모든 gRPC 입력값 검증
   - 의료 데이터 형식 강제 검사
   - 이상치 탐지 시스템

3. **안전한 시스템 구성**
   - Read-Only 파일 시스템 사용
   - 설정 변경 권한 제한
   - 변경 사항 감시 및 알림

## 4. 완화 전략 상세

### 4.1 기술적 완조

#### 4.1.1 인증 및 접근 제어

1. **다단계 인증**
   ```csharp
   // MFA 구현 예시
   public class MfaAuthService
   {
       public bool Authenticate(string username, string password, string otp)
       {
           // 1. 비밀번호 검증
           var passwordValid = _passwordHasher.Verify(password, _userRepository.GetHashedPassword(username));

           // 2. OTP 검증
           var otpValid = _otpService.Verify(otp, username);

           // 3. 지문/얼굴 인증 (선택적)
           var biometricValid = _biometricService.Verify(username);

           return passwordValid && otpValid;
       }
   }
   ```

2. **역할 기반 접근 제어(RBAC)**
   - 관리자: 시스템 전체 접근 권한
   - 의료진: 환자 데이터 읽기/쓰기
   - 응급진료: 비상 상황 특별 접근 권한

#### 4.1.2 데이터 보안

1. **데이터 암호화**
   - **전송 중**: TLS 1.3 필수
   - **저장 시**: AES-256
   - **키 관리**: HSM 또는 KMS
